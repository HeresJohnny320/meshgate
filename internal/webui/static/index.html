meshgate

Port forwards

Players connect to the edge (VPS) address; traffic is carried through the mesh to the target. Replaces hand-written iptables DNAT.

HTTPS routes

Point the hostname's DNS A record at the edge node's public IP. Certificates come from Let's Encrypt automatically.

Exit routes

Send a LAN device's (or a whole subnet's) internet traffic out through an exit node, e.g. 192.168.200.11 → vps: websites then see the exit's IP. Everything else on your network keeps using your normal connection, and every device can still reach the mesh. If the exit goes down, the router fails over to another exit node; with none left, Exit only routes have no internet and the others use the normal connection. One router uses one exit node at a time.

Access rules

Rules apply on nodes whose LAN policy is restricted (edit the node on the Nodes tab). There, mesh devices can only reach the IPs, VLANs and ports listed here. Port forwards and HTTPS routes are always allowed. On pfSense the rules are loaded as pf anchors.

Join token

Phones and laptops: scan the QR code with the meshgate app. Servers (Linux or pfSense): you get a one-line install command.

Official WireGuard app

For devices without meshgate. The device always connects through the relay you pick (no automatic switching).

Tokens

Live, refreshed every 3 seconds. Speeds are averaged over 5 seconds; totals count since meshgate started on the server that measures them. Port forwards and access rules are measured on Linux servers.

Monitors

Measure traffic to an IP, a port or both on a server node, e.g. a Minecraft proxy on the VPS talking to 192.168.1.51:25566 at home. A monitor only counts: it does not route, open or block anything (use Port forwards for that). Linux nodes.

Test service

A tiny responder for testing paths end to end. Turn it on for a server under Nodes → Edit → Test service port (e.g. 8099). It answers on TCP (open it in a browser or with curl) and UDP, and tells you which node answered and which address you came from.

Test a port forward: forward a VPS port to that node and port, then open http://<VPS IP>:<port> from outside (e.g. your phone on mobile data). Test HTTPS: add an HTTPS route to it and open the hostname. Turn it off again when done.

Web UI certificate

            
Each server's web UI uses HTTPS with its own (self-signed) certificate, made and renewed
              automatically for its mesh IP, localhost and LAN addresses. The browser warns once; before accepting,
              compare the SHA-256 fingerprint it shows with the one here. Read this list from a page you can trust:
              one opened over a mesh IP or localhost, or meshgate status on a server. A page that
              reached you through someone in the middle could show their fingerprint instead.
